# 📊 测试可视化图表指南

本目录包含 Raft-over-QUIC 性能测试的完整可视化数据。

## 📈 可用图表

### 1. 吞吐量 vs 并发 (throughput_vs_concurrency.svg)

**用途**: 显示随并发级别增加的写入吞吐量增长

**数据**:
- X轴: 并发等级 (4, 8)
- Y轴: 吞吐量 (ops/sec)
- 数据点:
  - C=4: 650 ops/sec
  - C=8: 846 ops/sec

**关键观察**:
- 吞吐量增长 30% (C=4 → C=8)
- 缩放效率: 1.3x (每并发增加 0.13x 吞吐量)
- 说明: QUIC 多流设计支持有效的并发

**应用场景**:
- 确定最优的并发配置
- 评估吞吐量瓶颈
- 负载计划和容量规划

---

### 2. 延迟分布 (latency_distribution.svg)

**用途**: 显示 p50、p95、p99 延迟百分位数

**数据**:
| 并发 | p50 (ms) | p95 (ms) | p99 (ms) |
|------|----------|----------|----------|
| C=4 | 5.5 | 8.3 | 12.4 |
| C=8 | 8.2 | 12.5 | 18.3 |

**关键观察**:
- p99 随并发线性增加
- p99/p50 比率稳定在 ~2.2x
- 分布特性良好（没有长尾）

**应用场景**:
- 评估用户体验 (p95 作为目标)
- 检测异常 (p99 应 <30ms)
- 监控延迟回归

## 🔍 如何解读图表

### 吞吐量图表

```
理想情况 (线性缩放):
  并发 4 → 4x 吞吐量
  并发 8 → 8x 吞吐量

实际情况 (Raft-over-QUIC):
  并发 4 → 2.0x 吞吐量 (好)
  并发 8 → 2.6x 吞吐量 (好)

缩放效率 = 实际 / 理想
  C=4: 50% 效率
  C=8: 32.5% 效率 (预期值递减)
```

### 延迟图表

```
健康指标:
  p50 < 10ms      ← 良好响应时间
  p95 < 20ms      ← 大多数请求快速
  p99 < 30ms      ← 最坏情况仍可接受

警告阈值:
  p99 > 50ms      ⚠️  检查网络延迟
  p99 > 100ms     🚨 需要优化
```

## 📋 性能基准解释

### 顺序写入 (Sequential Write)

- **并发度**: 1 (单线程)
- **吞吐量**: 320 ops/sec
- **用途**: 基线性能测试
- **延迟构成**:
  - 网络 RTT: ~2ms (QUIC/QUIC)
  - Raft 复制: ~1ms
  - 总计: ~3ms

### 并发写入 (Concurrent Write)

- **并发度**: 4, 8
- **吞吐量**: 650-846 ops/sec
- **用途**: 现实世界负载
- **注意**: 延迟随并发增加而增加

### 顺序读取 (Sequential Read)

- **并发度**: 1
- **吞吐量**: 1521 ops/sec
- **用途**: 本地读性能基线
- **注意**: 读比写快 4.7x（无 Raft 开销）

## 💡 性能优化建议

### 基于当前数据

1. **提高写吞吐量**
   - 考虑批处理 (combine multiple writes)
   - 增加 QUIC 连接缓冲区
   - 优化 Raft 参数

2. **降低延迟**
   - 升级网络到低延迟链路
   - 优化本地磁盘 I/O (如使用快照)
   - 调整 Raft 超时

3. **改善缩放**
   - 增加并发到 16+ 观察瓶颈
   - 监控 CPU 和内存使用
   - 考虑请求批处理
